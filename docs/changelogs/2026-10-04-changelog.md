# Changelog

All notable changes to the database setup in this project are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased] - 2026-10-04

### Added

- **Baseline database dump** (`scripts/maria-db/baseline.sql`): schema plus seed data,
  generated by running the real OpenEMR installer against MariaDB 12.3 and dumping the result.
- **Schema-only dump** (`scripts/maria-db/schema.sql`): kept as a reference and as a diff target for future structure changes.
- **Dockerfile** (`scripts/maria-db/dockerfile`): based on `mariadb:12.3`, copies `baseline.sql`
  into `/docker-entrypoint-initdb.d/` so it loads automatically on first start with an empty volume.
- **docker-compose.yml**: `db` service with a named volume (`dbdata`), a healthcheck,
  and configuration pulled from `.env`.
- **`.env` / `.env.example`**: database name, user, passwords and host port (3307).
  `.env` is gitignored; `.env.example` is committed with no secrets.
- **Automated import tests** (`tests/Db.Tests`): xUnit + Testcontainers. Starts a throwaway MariaDB,
  loads `baseline.sql`, and asserts the table count and that key seed tables
  (`users`, `globals`, `list_options`) are not empty.
- **Connection string guidance**: `appsettings.json` holds a placeholder; real values go in
  user secrets (local) or the `ConnectionStrings__OpenEmr` environment variable (deployment).

### How the baseline was produced

1. Ran the OpenEMR "insane" dev Docker stack (`openemr-8-4` + `mariadb`) with `EMPTY: yes`,
   so nothing was auto-installed.
2. Installed PHP dependencies inside the container (`composer install --no-dev`, then
   `composer dump-autoload -o --no-dev` to fix a "Class not found" error on the health endpoint).
3. Ran the OpenEMR setup wizard (Server Host `mariadb`, User Hostname `%`).
4. Dumped the database with `mariadb-dump --routines --triggers --events --single-transaction
   --default-character-set=utf8mb4 --result-file=...`, then copied it out with `docker cp`
   (avoids PowerShell's UTF-16 redirection problem).
5. Verified the import: table count, seed row counts, and app-user login.

### Issues encountered and resolved

- **Wizard created the DB user as `openemr@localhost`**, so the OpenEMR container could not connect.
  Fixed by dropping the user/database and retrying with User Hostname `%`.
  In the new setup the user is created by `MARIADB_USER` as `openemr@'%'`.
- **500 on `/meta/health/readyz`**: missing Composer dependencies in the bind-mounted checkout.
  Fixed with `composer install` and regenerating the autoloader.
- **Build errors in the test project**: missing `using MySqlConnector;` in `ImportTests.cs`, and the
  `baseline.sql` path in the `.csproj` pointing at a file that was not present.

### Known limitations / follow-ups

- The dump contains **dev leftovers** that should be cleaned before sharing the repo:
  the `Administrator` user and its hash (`users`, `users_secure`), rows in `log`, `api_log`
  and `log_comment_encrypt`, session rows, and environment-specific `globals` values.
- The same dump means every deployment shares the same generated keys and admin hash.
  For anything beyond local use, create the admin from environment variables at first run.
- The `openemr` DB account is **not** part of the dump (it lives in MariaDB's `mysql` schema);
  Compose creates it from `.env`.
- Init scripts run only on an empty volume. After editing `baseline.sql` or changing credentials in `.env`,
  run `docker compose down -v` and start again (this wipes data).
- `sqlconf.php` is not copied into this project; its values were translated into the connection string.
- Passwords and the admin login should be kept in a password manager, not in the repo.
